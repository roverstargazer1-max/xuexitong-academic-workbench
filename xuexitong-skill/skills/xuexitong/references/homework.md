# 作业与章节测验(双层画像 + 信息/成果工作流, 2026-09 校准)

适用于课程作业与章节测验。**全程遵守 SKILL.md 红线:列表扫描不碰 `work/task` 详情页,作答只暂存绝不自动提交,每步二次进页验证。**

## 0. 技术要点(先读,实测结论)

- **优先使用 MCP 工具做课程与列表扫描**:`xt_courses`、`xt_homework`、`xt_homework_all`、`xt_course_status`、`xt_seed_enc` 直接通过本地持久化 Cookie 会话请求学习通接口,0.3 秒完成扫描并自动在 `workspace/semesters/<学期>/<学科>/` 下建立目录骨架。
- **读写子 iframe 用 frameLocator**,例:`tab.playwright.frameLocator('#frame_content-zy')`。frame 内的 `locator.evaluate()` 在部分运行时**静默返回空对象**——frame 里只用 locator API(`innerText()` / `getAttribute()` / `allTextContents()` / `click()`),不要用 evaluate。主文档的 evaluate 正常。
- **不要 goto 子 iframe 的 src**:新版 `work/list` 直接报"无权限的操作!"(校验上下文)。

## 1. 作业仪表盘与扫描建骨架(优先走 MCP)

1. **秒级扫描活跃课程**:
   - 调用 MCP `xt_homework_all()`(默认仅扫描 `workspace/courses_index.json` 中状态为 `active` 本学期在修与 `long_term` 跨学期的课程,自动跳过 `archived` 往期归档课程)。
   - 若用户要求查看包含往期课程的全部作业,传 `xt_homework_all(include_archived=True)` 或按学期传 `semester="2026-2027-1"`。
   - 若用户指出某门课已结课或需调整分类(如夏令营/小学期课),调用 `xt_course_status(course="<课程名或ID>", status="archived", semester="...")` 持久化更新。
2. **自动生成本地骨架(扫描即建骨架)**:
   - `xt_homework` 与 `xt_homework_all` 会在 `workspace/semesters/<学期>/<学科>/` 下自动创建 `course_meta.md`(若不存在,绝不覆盖已有文件)、`通知/`、`资料/`、`作业/<安全作业名>/{信息, 成果}` 目录,并将列表元数据写入 `信息/作业元信息.json`。
   - **安全边界**:列表扫描阶段**严禁请求** `信息/作业元信息.json` 中的 `detail_url`(`work/task`),防止未开始作业(`answerId=0`)被提前分配答题记录。
3. **新课缺失 `enc` 时的浏览器一次性补种**:
   - 调用 `xt_courses()` 检查活跃课程是否全部带有 `[enc]` 标记。
   - 仅当某门 `active` / `long_term` 课程显示 `[no-enc]` 时,用浏览器进入该课程 → 点"作业"标签 → 读取 `#frame_content-zy` 的 `src` 属性提取 `stuenc` 与 `enc` 参数 → 调用 `xt_seed_enc(course_id, stuenc, work_enc)` 写入 `workspace/courses_index.json`。
4. **结合学科画像过滤非本组作业并输出待办**:
   - 读取对应学科的 `workspace/semesters/<学期>/<学科>/course_meta.md` 中的 `group` 字段(如 `group: "第1~10组"`),若未交作业标题明确属于其他分组(如"第11到21组"),在仪表盘中标为"非本组(无需提交)"而非紧急待办。
   - 汇总输出 markdown:`课程 | 作业 | 截止剩余时间 | 状态 | 本地目录路径`,按剩余时间升序排列,24h 内标 ⚠️。

## 2. 作答强制前置 Step 0:加载双层画像与聚合 `信息/`

**在解答任何一道题或编写任何一行代码前,必须按顺序完成以下 4 步(Completion Criterion: 画像已加载、`关联通知.md` 与 `题目原文.md` 已落盘、`信息/` 下所有用户文件已逐一读取)**:

1. **Step 0.1 读取双层用户画像**:
   - 读取 `workspace/profile.md`:获取学生 `name`、`student_id`、`major_class`、`enrollment`、默认附件命名模板 `attachment_naming_default` 以及操作系统/编程语言偏好。
   - 读取 `workspace/semesters/<学期>/<学科>/course_meta.md`:核对 `teacher`、所在分组 `group`(非本组作业立即提醒用户并停止作答)、学科专属附件命名规则 `naming_rule` 与教师特殊要求。
2. **Step 0.2 语义关联课程通知(`信息/关联通知.md`)**:
   - 检查 `workspace/semesters/<学期>/<学科>/通知/` 下的通知归档(若尚未同步通知,先按 `references/info.md` 同步课程通知)。
   - 由 Agent 结合通知正文语义(而非仅靠标题字符串匹配)判断是否有关于本作业的补充要求、提交格式变更、分组安排或截止时间调整,将相关通知摘录保存至 `作业/<作业名>/信息/关联通知.md`(无相关通知则注明"经排查课程通知,无额外补充要求")。
3. **Step 0.3 进入作答页提取完整题面与模板(`信息/题目原文.md`)**:
   - 从 `信息/作业元信息.json` 读取 `detail_url`(`mooc-ans/mooc2/work/task?...`),在浏览器中打开并记录重定向后的 `work/dowork?...` 完整 URL(供后续二次进页核验草稿使用;若跳 `work/preview` 说明已过期只读,如实告知用户)。
   - 在作答页主文档执行 `scripts/extract_questions.js` 提取 `{count, questions:[{index, typeName, stem, stemImgs, hasSecretFont, options, blanks, richEditors}]}`:
     - 若 `hasSecretFont: true`(含 `font-cxsecret` 加密字体)或含数学公式图片 `stemImgs`,采用**"看想分离"读题法**:先截图或拉取图片交给多模态视觉**只转录文字与 LaTeX 公式**(不推理答案)。
     - 若题干或题目中包含教师提供的附件模板(如 `.xls`、`.docx`、实验指导书),下载至 `作业/<作业名>/信息/` 目录。
   - 将整理好的完整题面、选项与公式转录统一写入 `作业/<作业名>/信息/题目原文.md`。
4. **Step 0.4 零配置遍历读取 `信息/` 下用户补充的所有文件(最高优先级!)**:
   - 列出 `作业/<作业名>/信息/` 目录下的全部文件。
   - 除自动生成的 `作业元信息.json`、`题目原文.md`、`关联通知.md` 外,**强制读取用户手动拖入的每一个文件**(无需用户按特定文件名重命名):
     - 对所有图片文件(`.png` / `.jpg` / `.jpeg` / `.webp`,如课堂板书照片、手写作业本截图、微信群补充通知截图)调用多模态视觉识别提取全部文字、公式与图表信息;
     - 对所有文档/表格/代码文件(`.md` / `.txt` / `.pdf` / `.docx` / `.xls` / `.xlsx` / `.cpp` / `.py`)提取文本与表格结构。
   - **优先级法则**:当学习通平台题面与用户在 `信息/` 下手动补充的截图/说明存在差异或补充约束时,**一律以用户补充信息为最高优先级要求**。

## 3. 作答策略与多题型自适应产出(`成果/`)

1. **参考依据优先级**:
   - 用户在 `<作业名>/信息/` 下的补充说明与截图 > `<作业名>/信息/关联通知.md` > `<学科>/资料/` 下的课程课件与提取笔记(见 `references/download.md`) > 外部答案源(`references/answer-sources.md`) > AI 推理。
2. **题型自适应产出契约(全部落盘至 `作业/<作业名>/成果/`)**:
   - **客观题与简答/计算题**:
     - 每题给出 **答案 + 理由/课件引用依据 + 置信度(高/中/低)**;多选题宁少勿滥;填空题严格匹配题面有效数字与单位口径;计算题写出关键公式与代入过程;简答题分点论述(150~400 字)。
   - **编程与上机实验题(`成果/src/`)**:
     - 在 `作业/<作业名>/成果/src/` 下编写完整源码、测试数据与自动化测试脚本;
     - 结合 `workspace/profile.md` 中的本地开发环境(如 `clang++ -std=c++17`、`python3`、`node`)**必须在本地实际编译并运行测试直至全部通过**,将编译命令、测试用例与运行输出记录进 `成果/答案审核单.md`。
   - **表格填写、实验报告与附件提交题(`成果/<命名规范文件>`)**:
     - 严格按照 `<学科>/course_meta.md` 的 `naming_rule`(或 `workspace/profile.md` 的 `attachment_naming_default`,如 `{student_id}_{name}_{homework_title}.xls`)在 `作业/<作业名>/成果/` 下生成最终可提交成品文件,绝不覆盖 `信息/` 下的原始模板。

## 4. 标准化答案审核单(`成果/答案审核单.md`)

每份作业必须在 `workspace/semesters/<学期>/<学科>/作业/<作业名>/成果/答案审核单.md` 生成统一格式的审核单,**低置信度题目必须在顶部单独高亮列出**:

```markdown
# 作业答案审核单：<作业标题>

- **学科**：<学科名称>（学期：`<学期>`）
- **workId**：`<workId>` | **平台状态**：已暂存未提交（二次核验通过）
- **画像与命名规范**：分组 `<group>` | 成品文件 `<成果文件名或无>`
- **信息源核对**：已读取 `题目原文.md`、`关联通知.md` 及用户补充文件 `<列出文件名或无>`

## ⚠️ 需重点复核题目（中/低置信度置顶）
- 第 X 题（置信度：低）：<简述不确定原因与复核建议>

## 题目作答明细
| 题号 | 题型 | 我的答案 | 理由 / 课件依据 / 本地测试结果 | 置信度 |
|---|---|---|---|---|
| 1 | 单选 | B | 依据《数据结构》第2章课件 P15 顺序表时间复杂度定义 | 高 |

## 简答 / 计算 / 编程实验详情
### 第 N 题
（完整作答内容、公式推导或 `成果/src/` 本地编译测试输出）
```

## 5. 平台回填、暂存与二次核验(红线!)

1. **网页回填(`scripts/fill_answers.js`)**:
   - 单选/判断:按**选项字母或显示文本**匹配 `.stem_answer .clearfix` 行并点击 `span.num_option`,**不依赖 data 属性**(重做后会随机化);点击后 1.6 秒检查 `check_answ` 选中高亮。
   - 多选:逐个点击,间隔 ≥1.5 秒。
   - 填空:写入 `textarea/input` 并派发 `input` + `change` 事件。
   - 简答/论述(UEditor):通过 `UE.instants` 定位题根内编辑器实例,**必须**调用 `setContent()` 后再调用 `sync()`。
2. **成品附件上传**:
   - 将 `作业/<作业名>/成果/` 下按画像规范命名的成品文件上传至作答页(UEditor 附件框或文件上传控件;大文件可走分块 base64 → `File` → `DataTransfer` → `input.files` 注入,出现 `<div module="insertAttach" objectid="..">` 后关闭弹窗)。
3. **只点"暂时保存"并二次进页验证**:
   - 只点击文本为**"暂时保存"**的按钮(弹出 `#popok` 确认层时真实点击确定),**绝不触碰"提交"按钮**。
   - **强制二次核验**:重新 goto 作答页 URL,核对选中项 `check_answ`、简答内容或已上传附件名称是否完整保留,核验无误后更新 `成果/答案审核单.md` 的暂存状态并向用户汇报。

### 提交与复盘(仅用户审核后当场明确授权时执行)

1. 仅当用户审阅 `成果/答案审核单.md` 后明确发出"提交"指令时,才可点击提交按钮并真实点击 `#popok` 确认层,截图留证。
2. 提交后若平台公布答案且允许重做,可提取标准答案写入审核单复盘;仅在用户再次明确授权后才可执行重做。
